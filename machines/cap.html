CAP

HackTheBox | 11 ago 2026 | Dificultad: Media

Introducción

CAP es una máquina Linux de dificultad media de HackTheBox. Durante la resolución comenzaremos realizando un reconocimiento de los servicios expuestos, para posteriormente identificar una funcionalidad vulnerable en el Security Dashboard que nos permitirá obtener una captura de tráfico.

Analizando dicha captura mediante Wireshark conseguiremos obtener unas credenciales válidas que nos permitirán acceder mediante SSH. Finalmente, mediante la enumeración de Capabilities encontraremos una configuración vulnerable en Python 3.8 que nos permitirá obtener una shell como ROOT.

1. Reconocimiento

Comenzamos realizando un escaneo de puertos para identificar los servicios expuestos en la máquina. 

nmap -Pn -p1-5000 --min-rate 5000 -vvv -oG allports 10.129.95.147

El escaneo nos permite identificar los siguientes puertos abiertos:

  • 21/tcp → FTP
  • 22/tcp → SSH
  • 80/tcp → HTTP

2. Enumeración de servicios

Una vez identificados los puertos abiertos, realizamos un segundo escaneo más específico utilizando scripts de enumeración y detección de versiones. 

nmap -p21,22,80 -sCV 10.129.95.147 -oG targeted

En esta ocasión obtenemos información más detallada sobre los servicios que se están ejecutando:

  • 21/tcp → vsftpd 3.0.3
  • 22/tcp → OpenSSH 8.2p1 Ubuntu
  • 80/tcp → HTTP / Gunicorn

Además, Nmap identifica el título de la aplicación web como Security Dashboard.

3. Security Dashboard

Accedemos al servicio web mediante el puerto 80. Al entrar en la aplicación observamos un Security Dashboard en el que aparecemos autenticados como el usuario Nathan.

En la parte superior de la aplicación podemos observar que la URL contiene el recurso: 

/data/1

Esto resulta interesante, ya que parece que la aplicación está utilizando un identificador numérico para acceder a diferentes capturas de datos.

Probamos a modificar manualmente el identificador de 1 a 0: 

/data/0

Al realizar este cambio conseguimos acceder a otro recurso que contiene información sobre una captura de tráfico.

La aplicación nos permite descargar esta captura, por lo que procedemos a analizarla con Wireshark.

4. Análisis del tráfico con Wireshark

Una vez descargado el archivo PCAP, lo abrimos con Wireshark para analizar las comunicaciones capturadas.

Durante el análisis observamos tráfico correspondiente al protocolo FTP.

FTP transmite las credenciales sin cifrar, por lo que podemos inspeccionar directamente los paquetes correspondientes a la autenticación.

Filtrando el tráfico FTP encontramos una petición USER correspondiente al usuario nathan y posteriormente una petición PASS.

Con esto conseguimos unas credenciales válidas para el usuario nathan.

5. Acceso mediante SSH

Como el puerto 22 está expuesto y disponemos de unas credenciales válidas, probamos a utilizarlas para acceder mediante SSH. 

ssh nathan@10.129.95.147

El acceso es correcto y conseguimos una shell como el usuario nathan.

Una vez dentro del sistema podemos acceder a la flag de usuario.

6. Enumeración de Capabilities

Con el acceso como usuario nathan, comenzamos a realizar la enumeración local del sistema buscando posibles vías para elevar privilegios.

Una de las comprobaciones que realizamos consiste en buscar binarios con Linux Capabilities: 

getcap -r / 2>/dev/null

Entre los resultados encontramos una entrada especialmente interesante: 

/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip

Python 3.8 dispone de la capability cap_setuid, lo que permite modificar el UID efectivo del proceso.

7. Escalada a ROOT

Aprovechando la capability cap_setuid de Python 3.8 podemos ejecutar código que cambie el UID del proceso a 0 y posteriormente obtener una shell. 

/usr/bin/python3.8 -c 'import os; os.setuid(0); os.execl("/bin/sh", "sh")'

Al ejecutar el comando obtenemos una shell y comprobamos nuestra identidad mediante: 

id

El resultado confirma que somos root: 

uid=0(root) gid=1001(nathan) groups=1001(nathan)

8. Conclusión

La máquina CAP comienza con una enumeración de los servicios expuestos, donde encontramos FTP, SSH y un servicio web.

La aplicación web nos permite acceder a diferentes capturas mediante identificadores numéricos. Modificando el identificador conseguimos acceder a una captura de tráfico que posteriormente analizamos con Wireshark.

El análisis del tráfico FTP nos permite recuperar las credenciales del usuario nathan, que reutilizamos para acceder mediante SSH.

Finalmente, la enumeración de Linux Capabilities revela que Python 3.8 dispone de la capability cap_setuid. Aprovechando esta configuración conseguimos cambiar nuestro UID a 0 y obtener una shell como ROOT.

CAP completada.
